dsh-model-auto-router — how to verify

This plugin ships plain ESM JavaScript with a pure, host-free core (src/pool.js, src/health.js, src/router.js), so the same behavioural suite can run in three ways. Pick whichever fits.

1. Node test runner — primary

cd F:/AI/dsh-model-auto-router
node --test test/

2. In-process self test — no tooling needed

Useful when Node is not on PATH (this environment, for example). The plugin runs the suite inside the DSH host at boot and can write a JSON report. Enable it in the profile entry:

- insert:
    - id: dsh-model-auto-router
      name: 'dsh-model-auto-router'
      selfTest: true
      selfTestOut: 'F:/AI/dsh-model-auto-router/selftest-report.json'

Or set DSH_MODEL_AUTO_ROUTER_SELFTEST=1. Each failure is logged as model-auto-router: self test FAILED — <case>: <reason>, and the summary as model-auto-router: self test N/M passed.

Note. Enable this before starting DSH, and note that the host caches plugin modules in its ESM registry — a plugin toggle or a DSH restart is needed for a changed file to be re-imported.

What the suite covers

  • pool parsing: duplicate rejection, provider inheritance, strategy validation
  • all five selection strategies, including weight extremes
  • failure classification: unavailable (429 / 5xx / overload / DNS) versus request fault (400 / 401 / context-length)
  • health thresholds, cooldown expiry, snapshot recovery
  • route pinning, subagent pool separation, compaction exclusion
  • failover to the next candidate, fall-through to the fallback pool, and not claiming a retry when nowhere healthy is left
